# Tandevia Workflow

Tandevia Workflow is [Activepieces](https://github.com/activepieces/activepieces) with Tandevia's
name and marks. Everything else is upstream: the engine, the pieces, the API, configuration keys
(`AP_*`) and the data model. Upstream's own README is in [README.upstream.md](README.upstream.md).

| what | where |
|---|---|
| branch | `tandevia` (default), cut from upstream release `0.92.3-hotfix.2` |
| image | `ghcr.io/tandevia/workflow:tandevia` (private), built by `.github/workflows/tandevia-image.yml` on every push to `tandevia` |
| edition | community (`AP_EDITION` unset); nothing under `packages/ee` or `packages/server/api/src/app/ee` is enabled |
| running | https://mkt.forscope.eu, marketing at Forscope, on the droplet `forscope-n8n` next to n8n. Compose, secrets, backups and the deploy command live in the private repo `jsulak-max/forscope-n8n` (`droplet/`) |

## What the rebrand changes

- The community edition always shows one theme, `defaultTheme` in
  `packages/server/api/src/app/flags/theme.ts`: name "Tandevia Workflow", Tandevia violet
  `#3A28E0`, logos served by the web app itself instead of Activepieces' CDN.
- Page title and favicon (`packages/web/vite.config.mts`), the marks in `packages/web/public`
  (`logo.svg`, `logo-180.png`, `logo-192.png`, `favicon.ico`, `tandevia/full-logo.png`).
  They are generated by `tandevia/generate-brand.py`; the Workflow mark is three blocks
  stepping down, joined like the steps of a flow, the last one lit.
- The MCP server's title, description, website and icons (`mcp-server-builder.ts`).
- Translation *values* (never keys) of the UI strings that name the product we run. Strings
  about Activepieces' own cloud, AI credits, telemetry and translation project stay as they are.

Upstream's copyright notice and licence stay in `LICENSE`.

## Updating from upstream

```bash
git remote add upstream https://github.com/activepieces/activepieces.git
git fetch upstream --tags
git checkout tandevia
git merge <new release tag>
```

Conflicts, if any, are in the files listed above. Push to `tandevia`; Actions builds the image.

## Deploy

```bash
ssh root@165.22.204.217 'cd /opt/n8n && docker compose pull workflow && docker compose up -d workflow'
```

The pull needs registry access to the private package on the droplet; see `droplet/` in
`jsulak-max/forscope-n8n` for how it is done there.

## GitHub Actions in this fork

Upstream's workflows are disabled in this repository; only `Tandevia Workflow image` runs.
